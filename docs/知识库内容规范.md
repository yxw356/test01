# 龙汇QA 知识库内容规范

> 用于初始化公共/部门/个人知识库的内容结构、清洗规则与 RAG 验收问题集。

## 1. 三类空间首批文档建议

| 空间 | 建议文档 | 负责角色 |
| --- | --- | --- |
| 公共知识库 | 员工手册、信息安全制度、报销/请假流程、IT FAQ、新人 onboarding | KNOWLEDGE_ADMIN |
| 部门知识库 | 部门 SOP、项目周报模板、客户话术、内部培训课件 | DEPT_LEAD |
| 个人知识库 | 个人笔记、草稿方案 | 各 USER |

## 2. 默认分类 taxonomy

系统启动时会自动预置以下分类（仅当分类表为空时）：

1. 制度与合规（PUBLIC）
2. 流程与操作指南（PUBLIC）
3. 产品与方案（PUBLIC）
4. 培训与学习（PUBLIC）
5. 项目资料（DEPARTMENT / default）
6. FAQ / 常见问题（PUBLIC）

## 3. 清洗规则建议

| 空间 | 规则名称 | 说明 |
| --- | --- | --- |
| PUBLIC | 公共知识严格去噪 | 去除页眉页脚、重复目录行 |
| DEPARTMENT | 部门知识保留结构 | 保留表格与编号列表 |
| PRIVATE | 个人知识轻量清洗 | 仅做基础空白规范化 |

上传前请在「清洗预览」中验证规则，避免误删有效正文。

## 4. 本地种子数据

本地 profile 可调用：

```bash
curl -X POST http://127.0.0.1:8081/api/v1/admin/dev/knowledge-samples
```

将创建公共、部门、个人、FAQ 四类样例文档及测试账号。

## 5. RAG 标准评测问题（10 条）

| # | 问题场景 | 期望结果 |
| --- | --- | --- |
| 1 | 公共制度问题（如“报销流程是什么”） | 命中 PUBLIC 文档并引用来源 |
| 2 | 部门专有流程（如“测试部门周报模板在哪”） | 仅本部门用户命中 DEPARTMENT 文档 |
| 3 | 跨部门用户问其他部门流程 | 0 命中或明确“暂无相关信息” |
| 4 | 个人笔记问题（上传 PRIVATE 文档后本人提问） | 仅本人命中个人文档 |
| 5 | 其他用户问某人的个人笔记 | 0 命中 |
| 6 | 表格数值问答（Excel 上传后） | 引用结构化表格块 |
| 7 | 切换聊天空间为“公共知识库”后提问 | 引用来源仅来自 PUBLIC |
| 8 | 切换聊天空间为某部门后提问 | 引用来源仅来自该 DEPARTMENT |
| 9 | 知识库页混合检索测试（带空间过滤） | 与当前选中空间一致 |
| 10 | 不存在的企业事实 | 不得编造，应说明知识库无依据 |

## 6. 内容治理 SOP

1. 上传草稿
2. 清洗预览
3. 等待索引完成（看板显示 indexed）
4. 部门负责人抽检
5. 开放问答引用

后续可扩展：文档版本号、过期提醒、待审核状态。
