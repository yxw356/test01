## 2. 对话落库与检索引用

### 2.1 设计说明

- **Redis**：仍用于多轮上下文（近 7 天、最多 20 条消息），保证追问体验。
- **MySQL `conversations` 表**：每轮问答持久化，供历史查询与合规留存。
- **结构化引用**：RAG 最终 Top-K 文档块序列化为 JSON，与问答一并存储。

### 2.2 数据表变更

`conversations` 表新增字段（JPA `ddl-auto: update` 或执行 `docs/databases/ddl.sql`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| session_id | VARCHAR(64) | Redis 会话 ID，关联多轮上下文 |
| retrieval_citations | TEXT | 检索引用 JSON 数组 |

引用 JSON 单条结构：

```json
{
  "index": 1,
  "fileMd5": "abc123...",
  "fileName": "报销制度.pdf",
  "chunkId": 3,
  "parentId": "parent-001",
  "score": 0.92,
  "snippet": "审批流程需经部门负责人..."
}
```

## 3. 知识库索引状态

### 3.1 状态定义

`file_upload.index_status`（与上传状态 `status` 分离）：

| 值 | 常量 | 含义 |
| --- | --- | --- |
| 0 | PENDING | 已合并，等待 Kafka 消费 |
| 1 | INDEXING | 正在解析 / 向量化 |
| 2 | INDEXED | 已写入 ES，可检索（历史数据默认 2） |
| 3 | FAILED | 索引失败，见 `index_error` |

### 3.2 状态流转

```text
上传合并成功 → PENDING（UploadController 发 Kafka 后）
     ↓
Kafka 消费开始 → INDEXING（FileProcessingConsumer）
     ↓
向量化成功 → INDEXED
     ↓（异常）
索引失败 → FAILED（写入 index_error）
```

### 3.3 后端要点

| 类 | 说明 |
| --- | --- |
| `FileIndexStatus` | 状态常量 |
| `FileIndexStatusService` | 更新 `index_status` / `index_error` |
| `FileUpload` | 新增 `indexStatus`、`indexError` |
| `FileProcessingConsumer` | 消费各阶段更新状态 |
| `DocumentController` | 列表 API 返回 `indexStatus`、`indexError` |

### 3.4 前端要点

| 文件 | 变更 |
| --- | --- |
| `enum/index.ts` | 新增 `IndexStatus` 枚举 |
| `knowledge-base/index.vue` | 「索引状态」列；概览「可检索 / 索引中」；待索引时每 5s 自动刷新 |

## 4. 索引失败重试

### 4.1 API

```http
POST /api/v1/documents/{fileMd5}/reindex
Authorization: Bearer <TOKEN>
```

- **权限**：文件所有者或 `ADMIN`
- **逻辑**：重新生成 MinIO 预签名 URL → 投递 Kafka → 状态置为 `PENDING`

## 6. Bug 修复：运行监控刷新 500

**现象**：运行监控页点击「刷新」返回 `Request failed with status code 500`。

**原因**：`MonitoringService.collectStatus()` 使用 `Map.of()` 组装 metrics，其中 `lastIndexFailureMessage`、`lastIndexFailureAt` 在未发生索引失败时为 `null`；`Map.of` 不允许 null 值，触发 `NullPointerException`。

**修复**：改用 `LinkedHashMap`，空值转为空字符串；`Instant` 格式化为字符串。

**涉及文件**：`MonitoringService.java`、`AdminOpsController.java`（补充错误日志）。

## 7. Bug 修复：管理端页面无数据（v1.3）

### 7.1 运行监控页空白

**原因**：`request()` 的 `transformBackendResponse` 已解包为 `data` 字段内容；页面仍访问 `response.data`，取值恒为 `undefined`。

**修复**：`admin-monitoring/index.vue` 改为 `status.value = response`。

## 8. Bug 修复：RAG 检索与问答准确性（v1.3）

### 8.1 现象

- 知识库已含「基地占地面积**200亩**」，问答却答「**20亩**」或输出大段英文思考过程
- 引用卡片显示「未知文件」，摘要从父块开头截取，看不到关键句

### 8.2 根因

| 问题 | 原因 |
| --- | --- |
| 检索其实命中 | ES/BM25 能命中 chunk（分数 ~2.8），问题在生成与上下文组装 |
| 数字误读 | 父块聚合后上下文过长（~3000 字），模型将 200 读成 20 |
| 英文思考 | Qwen3 默认输出 chain-of-thought；原过滤器未覆盖纯英文思考文本 |
| 未知文件 | RAG 链路未调用 `attachFileNames`，引用 `fileName` 为空 |
| MMR 干扰 | 「基地占地面积」被识别为「通用问答」，多样性过滤稀释最佳片段 |

### 8.3 修复措施

| 改动 | 说明 |
| --- | --- |
| `IntentDetector` | 「面积 / 占地 / 多少 / 总投资…」规则识别为 **查找定位**，关闭 MMR |
| `RagPipeline` | 精确定位类意图 **跳过父块聚合**，保留 child chunk |
| `ContextSnippetUtils` | 按问题关键词截取上下文 / 引用摘要（含「基地占地面积200亩」窗口） |
| `ChatHandler` | 落库前 `enrichWithFileNames`；`buildContext(query, docs)` 使用截取片段 |
| `RrfFusionService` | RRF 融合后保留各路 **最高原始 BM25 分**，供 Cross-Encoder stub 排序 |
| `DeepSeekClient` | 请求参数 `enable_thinking: false`；过滤英文思考；提示词要求 **数字不得改位** |
| `RetrievalCitation` | 引用摘要按 query 截取关键句 |
| `application.yml` | 系统规则增加「200亩 不可写成 20亩」类约束 |

### 8.4 验收

1. **新开对话**（避免旧会话错误历史干扰）提问：「基地占地面积」
2. 预期回答：**200亩**，引用摘要含「基地占地面积200亩」
3. 运行监控「问答次数」在完成后递增（内存计数，重启后端会清零）

## 9. Bug 修复：上传状态误报与续传鉴权（v1.3）

### 9.1 现象

- 文件已合并且 **可检索**，上传状态仍显示 **「上传中断」**
- 点击 **续传** 弹出 **重新登录**

### 9.2 根因

| 问题 | 原因 |
| --- | --- |
| 上传中断 | DB 中 `status=0`，但 `merged_at`、`index_status≥1` 已存在；前端凡 `status≠1` 一律标为 Break |
| `merged_at` 误导 | 字段曾使用 `@UpdateTimestamp`，索引更新也会刷新时间，与合并完成时间混淆 |
| 续传登出 | `GET /upload/status` 未加入 `OrgTagAuthorizationFilter` 白名单，缺少 `userId` 导致鉴权失败 |

### 9.3 修复措施

| 改动 | 说明 |
| --- | --- |
| `FileUpload.getEffectiveUploadStatus()` | 已合并或已进入索引流程 → 对外返回 `status=1` |
| `FileUpload.mergedAt` | 移除 `@UpdateTimestamp`，仅在 merge 成功时写入 |
| `FileIndexStatusService` | 标记 PENDING 及以上时同步 `status=1` |
| `DocumentController` | 列表 API 返回 `getEffectiveUploadStatus()` |
| `OrgTagAuthorizationFilter` | 放行 `/upload/status` 并注入 `userId` |
| 前端 `resolveUploadStatus()` | 结合 `mergedAt`、`indexStatus` 显示「已完成」 |

### 9.4 历史数据修复 SQL

```sql
UPDATE file_upload
SET status = 1
WHERE merged_at IS NOT NULL OR index_status >= 1;
```

> 已合并且可检索的文件 **无需续传**；仅 `status=0` 且无 `merged_at` 的才是真正的未完成上传。

**涉及文件**：

- `model/FileUpload.java`
- `service/FileIndexStatusService.java`
- `config/OrgTagAuthorizationFilter.java`
- `controller/DocumentController.java`
- `frontend/src/views/knowledge-base/index.vue`

## 12. 验收步骤

### 12.1 索引状态

1. 登录 → 知识库 → 上传 txt/pdf  
2. 观察「索引状态」：待索引 → 索引中 → 可检索  
3. 索引完成后混合检索 / 问答应能命中内容  

### 12.2 索引重试

1. 模拟失败（如关闭 Embedding 8001 后上传）或使用失败记录  
2. 点击「重试索引」或调用 `POST .../reindex`  
3. 恢复服务后状态变为可检索  

### 12.3 对话与引用

1. 问答工作台提问  
2. 助手回复下方出现「参考来源」  
3. 点击来源文件名 → 打开预览  
4. 刷新页面后历史仍可从 MySQL 加载（管理员在「聊天记录」可查）  

### 12.4 管理端

1. 使用 `admin` 登录  
2. 打开「审计日志」→ 应有列表数据与正确总数  
3. 打开「运行监控」→ 刷新，应显示 Redis/ES/Kafka/vLLM 与问答/索引指标（不再空白或 500）

### 12.5 上传状态（v1.3）

1. 刷新知识库列表  
2. 已上传且可检索的文件：**上传状态 = 已完成**，**索引状态 = 可检索**  
3. 不应再对已完成文件显示「上传中断」；一般无需点续传  

### 12.6 RAG 事实问答（v1.3）

1. **新开对话**，提问：「基地占地面积」  
2. 预期：**200亩**；引用摘要含「基地占地面积200亩」；文件名非 unknown  
3. 回答为简体中文，无大段英文思考过程  

### 12.7 问答工作台交互（v1.4）

1. 登录后打开 **RAG 问答工作台**（`/#/chat`）  
2. 中间应显示历史对话或「开始一次知识库问答」空状态，**不应整页空白**  
3. 输入问题发送 → **当前页立即出现** 用户气泡与助手 loading/流式回复  
4. 助手消息下方「参考来源」→ 点击文件名 → **弹窗预览**（非消息流内嵌条）  
5. 弹窗内可 **下载**；未知类型文件显示通用文档图标，**无 DFLT 字样**  
6. 输入框下方连接状态为 **绿色插头** 时可正常问答；红色时需刷新或重新登录  

### 12.8 运行监控处置提示（v1.5）

1. 打开 **运行监控**（`/#/admin-monitoring`）并刷新  
2. **仅向量 DOWN**：出现黄色「向量模型未启动」，含 OOM 与 `手工启动指南` 第 3 步说明  
3. **仅对话 DOWN**：出现蓝色/黄色「对话模型未启动」，提示按第 2 步启动 8000（问答可用）  
4. **两者均 DOWN**：同时出现上述两条，并建议先 8001 索引、再 8000 问答  
5. **问答优先部署**：仅启动 8000 时，向量 DOWN 为预期，已有 ES 数据仍可问答

## 14. Bug 修复：RAG 问答工作台交互与布局（v1.4）

### 14.1 现象

- 问答工作台每条助手消息下方常出现 **「下载 + DFLT」** 条，挤占聊天区，布局杂乱
- 输入问题并发送后，**当前页面不出现问答**（或一闪即没）
- 打开 `/#/chat` 时中间对话区 **完全空白**（标题与输入框可见，列表不可见）
- WebSocket 未连接时仍可点发送，助手侧无响应且体验不明确

### 14.2 根因

| 问题 | 原因 |
| --- | --- |
| 下载 / DFLT 常驻 | `FilePreview` 直接嵌在每条 `ChatMessage` 内且未按 `visible` 隐藏；`dflt.svg` 底部含「DFLT」字样 |
| 发送后无问答 | 进入页时 `users/conversation` 异步返回后 **整表覆盖** `list`，覆盖刚 push 的本地消息 |
| 页面空白 | 聊天列表 `NScrollbar` 使用 `h-0 flex-auto`，父级 flex 高度链不完整，**可视高度为 0** |
| WS 不稳定 | WebSocket URL 在 store 初始化时写死 token；空 token 或登录后 token 变更未重连 |

### 14.3 修复措施

| 改动 | 说明 |
| --- | --- |
| 预览改为弹窗 | `chat-list.vue` 与知识库页一致，使用 `NModal` + 单例 `FilePreview`；`chat-message.vue` 移除内嵌预览 |
| 预览状态上收 | `store/modules/chat/index.ts` 提供 `openFilePreview` / `closeFilePreview` |
| 进行中对话保护 | `getList()` 在 `isActiveChat()`（pending/loading）时不覆盖本地 `list` |
| 布局最小高度 | `chat/index.vue`、`chat-list.vue` 增加 `min-h-500px` / `min-h-360px` 与 flex 高度链 |
| WebSocket | `wsUrl` 改为 `computed` 随 `authStore.token` 更新；有 token 时才 `immediate` 连接 |
| 发送前检查 | WS 非 `OPEN` 时提示「正在连接…」并保留输入，避免假发送 |
| 流式解析 | `JSON.parse` 增加空值与 try/catch，避免异常中断后续 chunk |
| 通用文件图标 | 未知扩展名使用 Iconify `mdi:file-document-outline`，知识库列表同步 |

- `frontend/src/views/chat/index.vue`

- `frontend/src/views/chat/modules/chat-message.vue`

### 17.5 对话模型配置（监控 401 排障）

**现象**：运行监控或知识库「上传服务状态」中 **对话模型 (8000) DOWN**，详情类似：

`401 Unauthorized from GET https://api.deepseek.com/models`

**原因**：合并后曾一度将 `deepseek.api.url` 默认设为 DeepSeek 云端，而本机实际使用 **vLLM 8000**；未配置云端 Key 时健康检查返回 401。**不代表 8000 进程未启动。**

**当前默认（`application.yml`）** — 本机 vLLM：

```yaml
deepseek.api.url: http://127.0.0.1:8000/v1
deepseek.api.model: Qwen3.6-35B-A3B
deepseek.api.key: vllm_api_key_12345
```

使用 DeepSeek 云端时，启动前设置：

```bash
export DEEPSEEK_API_URL=https://api.deepseek.com
export DEEPSEEK_API_MODEL=deepseek-chat   # 按账号可用模型填写
export DEEPSEEK_API_KEY=<你的密钥>
```

健康检查逻辑：`MonitoringService` 请求 `{deepseek.api.url}/models`，与真实问答共用同一配置。

### 17.6 合并后验证步骤

1. **重启后端 8081**（必须，否则仍为旧字节码/旧配置）。
2. **重启或刷新前端 9527**（`pnpm dev` 或重新 `pnpm build`）。
3. Docker 中间件保持运行即可，一般无需 `docker compose down`。
4. 浏览器 **退出后重新登录**（或无痕窗口），避免旧 JWT 缺少新角色声明。
