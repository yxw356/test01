# 龙汇QA全面测试方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to execute this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 对龙汇QA从账号权限、知识库上传、数据清洗、制度审计、RAG问答、来源追溯、培训题库、PPT、知识图谱、运行监控到50人并发体验进行完整验收。

**Architecture:** 测试按“基础环境 -> 核心业务 -> AI效果 -> 权限安全 -> 稳定性压测 -> 用户体验”分层推进。每个用例必须记录账号、角色、知识库范围、输入数据、预期结果、实际结果和问题等级。

**Tech Stack:** Spring Boot 3.4、Vue/Vite、H2/MySQL、MinIO、Kafka、Elasticsearch、DeepSeek/OpenAI-compatible LLM、WebSocket、Naive UI、ECharts。

---

## 1. 测试目标

| 目标 | 验收标准 |
| --- | --- |
| 功能完整 | 主要页面和接口均可完成闭环，不出现阻断级错误 |
| 权限可靠 | 普通用户、部门成员、部门负责人、知识管理员、超级管理员无越权 |
| 知识可用 | 上传文件重启后仍存在，可检索、可预览、可引用 |
| 问答准确 | 知识库命中问题能基于来源回答；无依据时不编造 |
| 来源可信 | 回答来源默认收起，展开后可点击预览文件 |
| 培训可用 | 部门题库、自动阅卷、排名、PPT生成可完成 |
| 运行稳定 | 20人日常可用，50人压测无系统崩溃 |
| 可运维 | 监控、操作日志、审计日志能定位问题 |

## 5. 功能测试清单

### 5.1 登录与账号

| 编号 | 用例 | 预期 |
| --- | --- | --- |
| AUTH-01 | 正确账号密码登录 | 进入系统，生成 token |
| AUTH-02 | 错误密码登录 | 明确提示失败，不进入系统 |
| AUTH-03 | `hr` 短用户名登录 | 如果账号存在，应允许登录，不被前端长度规则拦截 |
| AUTH-04 | 外部注册接口 | 返回禁止注册 |
| AUTH-05 | 个人中心修改密码 | 修改成功后旧密码失效 |
| AUTH-06 | 超级管理员新增账号 | 账号可登录，角色与部门正确 |
| AUTH-07 | 部门负责人新增部门成员 | 只能给本部门创建成员 |
| AUTH-08 | 删除用户 | 被删用户不能登录，日志可追踪 |
| AUTH-09 | 修改用户名 | 新用户名可登录，旧用户名失效 |

## 10. 测试执行顺序

- [ ] **Step 1: 环境冒烟**
  - 启动前端、后端、MinIO、Kafka、ES。
  - 登录 `admin`。
  - 打开知识库、聊天、运行监控。
  - 预期：页面均可打开，后端无启动错误。

- [ ] **Step 2: 准备账号和部门**
  - 创建人事行政部、销售部。
  - 创建 `hr_lead/hr_user/sales_lead/sales_user/kb_admin`。
  - 预期：各账号可登录，角色部门正确。

- [ ] **Step 3: 上传测试数据**
  - 上传公共制度包、人事制度包、销售案例包、脏数据包。
  - 等待清洗和索引完成。
  - 预期：列表状态为已完成、可检索。

- [ ] **Step 4: 执行权限测试**
  - 用每个账号检查文档列表、预览、下载、删除。
  - 预期：无越权。

- [ ] **Step 5: 执行 RAG 问答测试**
  - 使用第 6 节评测集逐题测试。
  - 记录答案分、来源、是否编造。
  - 预期：达到上线门槛。

- [ ] **Step 6: 执行治理功能测试**
  - 维护问答对、术语、案例。
  - 验证标准问答、同义词召回、案例辅助回答。

- [ ] **Step 7: 执行培训功能测试**
  - 生成 PPT、题库。
  - 部门成员答题并查看排名。

- [ ] **Step 8: 执行图谱测试**
  - 打开知识网络和文件拓扑。
  - 验证节点、边、状态、交互。

- [ ] **Step 9: 执行日志与监控测试**
  - 检查登录日志、操作日志、运行监控组件状态。
  - 预期：可定位用户、设备、操作和异常。

- [ ] **Step 10: 执行50人压测**
  - 按第 7 节命令运行。
  - 导出压测结果和后端日志。
  - 预期：满足性能指标。

- [ ] **Step 11: 回归测试**
  - 修复 P0/P1 后重新执行相关模块。
  - 全部 P0/P1 关闭后进入用户试用。

## 12. 当前优先级建议

| 优先级 | 测试内容 | 原因 |
| --- | --- | --- |
| 1 | 权限隔离、文件预览、来源点击 | 直接影响数据安全和可信度 |
