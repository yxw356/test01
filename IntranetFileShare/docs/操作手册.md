## 1. 系统概述

本系统用于**内网环境下的角色分权文件访问**，借鉴 Windows 共享（用户 / 组 / 共享 / ACL）的设计思路，但采用集中控制面 + 分布式 Agent 的方式，避免各 PC 直接暴露 SMB 共享。

**核心能力：**

- 统一账户、角色、组、共享目录管理
- 基于 ACL 的细粒度读 / 写 / 删 / 管理权限
- 各 PC 注册本地目录，经控制面鉴权后供他人访问
- 操作审计（登录、列表、上传、下载、删除）

**不做的事（v1）：**

- 不对接 AD/LDAP
- 不提供 RDP 远程桌面
- 不同步 Windows NTFS ACL

## 2. 架构与组件

```
                    ┌─────────────────────────┐
                    │   Server（控制面）        │
                    │   端口 8443 + SQLite     │
                    └───────────┬─────────────┘
                                │
          ┌─────────────────────┼─────────────────────┐
          │                     │                     │
    ┌─────▼─────┐        ┌──────▼──────┐       ┌──────▼──────┐
    │ Admin WPF │        │ Client WPF  │       │ Agent 服务  │
    │  管理端    │        │   客户端     │       │ 各共享 PC   │
    └───────────┘        └──────┬──────┘       └──────┬──────┘
                                │                     │
                                │  FileToken          │ 本地目录
                                └────────────────────►│ D:\Finance
```

| 组件 | 程序 | 部署位置 | 端口 |
|------|------|----------|------|
| Server | `IntranetFileShare.Server.exe` | 内网服务器 1 台 | 8443 |
| Admin | `IntranetFileShare.Admin.exe` | 管理员 PC | — |
| Client | `IntranetFileShare.Client.exe` | 用户 PC | — |
| Agent | `IntranetFileShare.Agent.exe` | 需要共享本机目录的 PC | 5001 |

**访问流程：**

1. 用户 Client 登录 Server，获取 JWT
2. Client 请求共享列表 → Server 按 ACL 过滤
3. 用户浏览文件 → Client 向 Server 申请短期 FileToken（5 分钟）
4. Client 携带 FileToken 访问目标 PC 的 Agent 读取/写入文件

## 4. 安装部署

### 4.1 方式一：一键安装（推荐）

1. 解压 `IntranetFileShare-Full-win-x64.zip`
2. **以管理员身份**运行 `install.bat`
3. 文件安装到 `C:\Program Files\IntranetFileShare\`
4. 桌面自动创建「内网文件共享-管理端」「内网文件共享-客户端」快捷方式

### 4.2 方式二：分组件安装

按需解压对应 zip，手动复制到目标目录。

### 4.3 部署 Server（内网服务器）

**步骤 1：放置文件**

将 `Server/` 目录复制到服务器，例如 `D:\IntranetFileShare\Server\`。

**步骤 2：编辑配置**

编辑 `appsettings.json`：

```json
{
  "ConnectionStrings": {
    "Default": "Data Source=D:\\IntranetFileShare\\data\\intranet.db"
  },
  "Jwt": {
    "Secret": "请替换为至少32字符的随机密钥！！！",
    "Issuer": "IntranetFileShare",
    "AccessTokenMinutes": 15,
    "FileTokenMinutes": 5
  },
  "Urls": "http://0.0.0.0:8443"
}
```

**步骤 3：创建数据目录**

```powershell
mkdir D:\IntranetFileShare\data
```

**步骤 4：启动 Server**

```powershell
cd D:\IntranetFileShare\Server
.\IntranetFileShare.Server.exe
```

看到监听 `8443` 即成功。首次启动自动创建数据库。

**步骤 5：防火墙**

```powershell
New-NetFirewallRule -DisplayName "IntranetFileShare Server" `
  -Direction Inbound -Protocol TCP -LocalPort 8443 -Action Allow
```

**步骤 6：注册 Windows 服务（可选，开机自启）**

```powershell
sc create IntranetFileShareServer `
  binPath= "D:\IntranetFileShare\Server\IntranetFileShare.Server.exe" `
  start= auto DisplayName= "Intranet File Share Server"
sc start IntranetFileShareServer
```

**步骤 7：验证**

浏览器访问：`http://服务器IP:8443/health`  
应返回 `{"status":"UP"}`

### 4.4 部署 Agent（共享本机目录的 PC）

见 [第 8 章](#8-agent-配置共享本机目录)。

### 4.5 部署 Admin / Client

解压后直接运行 exe，无需额外配置。Admin 和 Client 只需知道 Server 地址即可。

## 6. 管理端操作

启动 `IntranetFileShare.Admin.exe`

### 6.1 登录

| 字段 | 示例 |
|------|------|
| 服务器 | `http://192.168.1.10:8443` |
| 用户名 | `admin` |
| 密码 | （你的密码） |

> 仅 `Admin` / `SuperAdmin` 角色可登录管理端。

### 6.2 用户管理

**创建用户：**

1. 切换到「用户管理」
2. 填写：用户名、密码、显示名、角色
3. 点击「创建用户」

**角色说明：**

| 角色 | 文件读 | 文件写 | 文件删 | 管理共享 | 管理端 |
|------|--------|--------|--------|----------|--------|
| Viewer | ✓ | ✗ | ✗ | ✗ | ✗ |
| User | ✓ | ✓ | ✗ | ✗ | ✗ |
| Manager | ✓ | ✓ | ✓ | ✓ | ✗ |
| Admin | ✓ | ✓ | ✓ | ✓ | ✓ |
| SuperAdmin | ✓（绕过 ACL） | ✓ | ✓ | ✓ | ✓ |

**删除用户：** 在用户列表点击「删除」（不可删除 SuperAdmin）。

### 6.3 组管理

1. 切换到「组管理」
2. 输入组名（如 `财务部`）→ 创建
3. 创建用户时在组 ID 中引用（当前版本创建后可在数据库或后续版本 UI 中绑定）

> ACL 中使用 **组 ID**（数字），可在组列表查看。

### 6.4 共享管理

**前置条件：** 目标 PC 的 Agent 已安装并在线。

1. 切换到「共享管理」
2. 查看 Agent 列表：确认机器名、IP、状态为 **Online**
3. 创建共享：

| 字段 | 示例 | 说明 |
|------|------|------|
| Agent ID | `1` | Agent 列表中的 ID |
| 逻辑名 | `finance` | 用户看到的共享名称 |
| 本地路径 | `D:\Finance` | Agent PC 上的实际目录 |

4. 记录创建后的 **Share ID**（列表第一列）
5. 到 Agent PC 的 `agent.json` 中添加 ShareId 映射（见第 8 章）
6. 重启 Agent 服务

### 6.5 ACL 配置

1. 切换到「ACL 配置」
2. 下拉选择目标共享
3. 添加 ACL 条目：

| 字段 | 说明 | 示例 |
|------|------|------|
| 主体类型 | User / Group / Role | `Group` |
| 主体 ID | 对应 ID 或角色名 | `1`（组 ID） |
| 动作 | Read / Write / Delete / Manage | `Read` |
| 效果 | Allow / Deny | `Allow` |

**常用 ACL 示例：**

```
# 财务部组只读 finance 共享
Group / 1 / Read / Allow

# 禁止某用户访问
User / 5 / Read / Deny

# 所有 Manager 可写
Role / Manager / Write / Allow

# 共享 owner 自动获得 Manage（创建时系统添加）
```

**删除 ACL：** 在列表点击「删除」。

### 6.6 审计日志

切换到「审计日志」→ 点击「刷新」。

| 动作 | 含义 |
|------|------|
| Login | 用户登录 |
| List | 查看共享列表 |
| Download | 下载文件（申请 Read Token） |
| Upload | 上传文件 |
| Delete | 删除文件 |
| ShareCreate / ShareUpdate | 共享变更 |
| AclChange | ACL 变更 |
| UserChange | 用户变更 |

## 7. 客户端操作

启动 `IntranetFileShare.Client.exe`

### 7.1 登录

| 字段 | 示例 |
|------|------|
| 服务器 | `http://192.168.1.10:8443` |
| 用户名 | `zhangsan` |
| 密码 | （你的密码） |

登录成功后，左侧显示**你有权访问的共享**。

### 7.2 浏览文件

1. 左侧点击共享名称
2. 右侧显示文件列表
3. **双击目录**进入子目录
4. 点击「上级目录」返回
5. 点击「刷新」重新加载

> 若共享显示 Agent 离线，无法浏览，请联系管理员检查 Agent 服务。

### 7.3 文件操作

| 按钮 | 操作 | 前提 |
|------|------|------|
| 下载 | 保存文件到本机 | 选中文件（非目录）+ 有 Read 权限 |
| 上传 | 从本机选择文件上传 | 有 Write 权限 |
| 删除 | 删除选中文件或目录 | 有 Delete 权限 |

### 7.4 权限不足的表现

- 共享不出现在列表 → 无 Read ACL
- 上传/删除按钮可用但操作失败 → 403，检查 ACL 和角色上限
- Agent 离线 → 提示「Agent 离线，无法访问该共享」

## 8. Agent 配置（共享本机目录）

在**需要让别人访问本机文件夹**的 PC 上部署 Agent。

### 8.1 安装

**方式 A：一键脚本（管理员 PowerShell）**

```powershell
cd C:\Program Files\IntranetFileShare
.\scripts\install-agent.ps1 -ServerUrl "http://192.168.1.10:8443"
```

**方式 B：手动**

1. 复制 `Agent/` 到 `C:\Program Files\IntranetFileShare\Agent\`
2. 注册 URL ACL：

```powershell
netsh http add urlacl url=http://+:5001/ user=Everyone
```

3. 注册服务：

```powershell
sc create IntranetFileShareAgent `
  binPath= "C:\Program Files\IntranetFileShare\Agent\IntranetFileShare.Agent.exe" `
  start= auto
sc start IntranetFileShareAgent
```

4. 防火墙（仅内网）：

```powershell
New-NetFirewallRule -DisplayName "IntranetFileShare Agent" `
  -Direction Inbound -Protocol TCP -LocalPort 5001 `
  -Action Allow -RemoteAddress 192.168.1.0/24
```

### 8.2 配置 agent.json

文件位置：`C:\Program Files\IntranetFileShare\Agent\agent.json`

```json
{
  "ServerUrl": "http://192.168.1.10:8443",
  "ListenPort": 5001,
  "AgentId": 0,
  "AgentKey": "",
  "MachineName": "",
  "Shares": [
    {
      "ShareId": 1,
      "LocalPath": "D:\\Finance"
    }
  ]
}
```

| 字段 | 说明 |
|------|------|
| ServerUrl | 控制面地址 |
| ListenPort | Agent 监听端口，默认 5001 |
| AgentId / AgentKey | 首次启动自动注册填充，**勿手动改** |
| Shares | ShareId（管理端创建）→ 本地路径映射 |

> **ShareId 必须与管理端创建的共享 ID 一致，LocalPath 必须是本机真实存在的目录。**

### 8.3 完整配置流程示例

假设 PC-A（192.168.1.20）要共享 `D:\Finance`：

1. PC-A 安装并启动 Agent
2. 管理端 → 共享管理 → 看到 Agent「PC-A」Online，ID=1
3. 管理端 → 创建共享：Agent ID=1，逻辑名=`finance`，路径=`D:\Finance`
4. 创建成功，Share ID=1
5. PC-A 编辑 `agent.json`：

```json
"Shares": [{ "ShareId": 1, "LocalPath": "D:\\Finance" }]
```

6. 重启 Agent：

```powershell
sc stop IntranetFileShareAgent
sc start IntranetFileShareAgent
```

7. 管理端配置 ACL，Client 用户验证访问

### 8.4 一台 PC 共享多个目录

```json
"Shares": [
  { "ShareId": 1, "LocalPath": "D:\\Finance" },
  { "ShareId": 2, "LocalPath": "D:\\Projects" }
]
```

每个 ShareId 对应管理端创建的一条共享记录。

## 9. 权限模型说明

### 9.1 判定顺序

```
1. SuperAdmin → 直接允许
2. DENY 规则 → 任一命中则拒绝
3. ALLOW 规则（User + Group + Role）→ 合并
4. 角色能力上限 → 如 Viewer 即使有 Write ALLOW 也不允许写
5. 共享 Owner → 默认拥有读权限
```

### 9.2 ACL 动作含义

| 动作 | 对应操作 |
|------|----------|
| Read | 查看共享、列目录、下载 |
| Write | 上传文件 |
| Delete | 删除文件/目录 |
| Manage | 修改共享信息、配置 ACL |

### 9.3 主体类型

| 类型 | PrincipalId 填什么 |
|------|-------------------|
| User | 用户 ID（用户管理列表第一列） |
| Group | 组 ID（组管理列表第一列） |
| Role | 角色名：`Viewer` / `User` / `Manager` / `Admin` |

## 10. 典型业务场景

### 场景 A：财务部共享文件夹，全员只读

1. 创建组「财务部」，组 ID=2
2. PC-Finance 安装 Agent，共享 `D:\Finance`，Share ID=1
3. ACL：`Role / User / Read / Allow`（所有登录用户可读）
4. 或 ACL：`Group / 2 / Read / Allow`（仅财务部）

### 场景 B：项目资料，项目组成员读写

1. 创建组「项目A」，组 ID=3
2. 创建共享 `project-a`
3. ACL：
   - `Group / 3 / Read / Allow`
   - `Group / 3 / Write / Allow`
4. 成员角色设为 `User` 或 `Manager`

### 场景 C：禁止某人访问

1. ACL：`User / 5 / Read / Deny`
2. DENY 优先，该用户看不到此共享

### 场景 D：只安装 Client 的用户

用户 PC 只需安装 Client，不需要 Agent。仅在本机需要**对外提供目录**时才装 Agent。

## 12. 故障排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 登录失败 | Server 未启动 / 地址错误 / 防火墙 | 检查 `:8443/health`、防火墙规则 |
| 管理端提示需要管理员 | 账户角色非 Admin | 用 admin 登录或提升角色 |
| 共享列表为空 | 无 ACL 授权 | 管理端添加 Read Allow |
| Agent 显示 Offline | 服务未运行 / 网络不通 | `sc query`、检查 ServerUrl |
| 文件列表失败 | agent.json ShareId 未映射 | 核对 ShareId 和 LocalPath |
| 文件列表失败 | 本地目录不存在 | 创建目录或修正路径 |
| 403 无权限 | ACL 不足或角色上限 | 检查 ACL + 角色（Viewer 不可写） |
| Agent 离线提示 | 心跳超时（>2 分钟） | 重启 Agent，检查 Server 连通 |
| 下载/上传失败 | FileToken 过期（5 分钟） | 重新操作即可 |
| HttpListener 403 | 未注册 URL ACL | `netsh http add urlacl url=http://+:5001/ user=Everyone` |

### 12.1 网络连通性测试

```powershell
# 从 Client PC 测试 Server
Test-NetConnection 192.168.1.10 -Port 8443

# 从 Client PC 测试 Agent
Test-NetConnection 192.168.1.20 -Port 5001
```

### 12.2 重置 admin 密码

若忘记密码，停止 Server，删除 `intranet.db` 后重启（**会丢失所有数据**），或直接用 SQLite 工具修改。

## 13. 安全规范

1. **首次登录后立即修改** `admin` 默认密码
2. **更换 Jwt.Secret** 为 32 字符以上随机字符串
3. **Server / Agent 不映射到公网**
4. 防火墙 Agent 5001 **限制来源 IP 段**
5. 生产环境使用 **HTTPS**（IIS 反向代理或 Kestrel 证书）
6. 定期查看**审计日志**，关注异常下载/删除
7. 定期**备份 intranet.db**
8. 员工离职：**禁用账户** + 检查 ACL 中的 User 条目
